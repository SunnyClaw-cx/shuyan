# 枢言 Web 应用示例：留言板

一个**前后端齐全**的最小 Web 应用，用来回答一个问题：

> 枢言能不能拿来做完整的应用程序？

**结论：能，但需要一层薄薄的宿主适配。** 下面把这个结论的依据与边界说清楚。

---

## 架构：业务在枢言里，宿主只管收发

```
   浏览器
      │  HTTP 请求
      ▼
┌──────────────────────┐
│   服务.py（约 127 行） │   ← 宿主适配层（Python）
│   监听 / 解析 / 回写   │      不含任何业务逻辑
└──────────┬───────────┘
           │  调用 处理请求(路径, 表单)
           ▼
┌──────────────────────┐
│   应用.sy（枢言）      │   ← 全部业务逻辑在这里
│   · 路由分发          │
│   · 状态码决策        │
│   · HTML 渲染         │
│   · 数据增删查        │
└──────────────────────┘
```

**职责边界是刻意的**：

| 层 | 内容 | 用什么写 |
|---|---|---|
| 网络适配 | 监听端口、解析 HTTP、回写响应 | Python（宿主） |
| 业务逻辑 | 路由、状态码、渲染、数据处理 | **枢言** |
| 视图 | HTML / CSS 字符串 | **枢言**（`渲染首页()`） |

---

## 运行

```bash
# 启动服务（浏览器打开 http://127.0.0.1:8000）
python projects/留言板/服务.py

# 端到端自测（21 项，启动临时端口，跑完自动退出）
python projects/留言板/自测.py
```

无需任何第三方依赖 —— 网络层用的是 Python 标准库 `http.server`。

## 这个示例暴露的三件事

### 1. 枢言的业务表达能力够用

路由分发（`如果 / 否则若 / 否则`）、HTML 渲染（字符串拼接 + 遍历）、
数据建模（结构体）、集合操作（`入列`/`长度`/`有键`）—— 全部用现有语法完成，
**没有为了写这个应用而新增任何语言特性**。

### 2. 缺的是网络层，不是语言层

枢言标准库现有的 11 个模块（`文本` `列表` `映射` `数学` `随机` `时间`
`文件` `系统` `编码` `加密` `正则`）**全是本地能力**，没有网络设施。

因此当前做 Web 应用必须自带一层宿主适配。这是**可以补的**——
Python 标准库的 `http.server` 已验证可用，实现 `网络` 模块不违背「零第三方依赖」。

### 3. 中文路由是个真问题，已处理

URL 里的中文路径在传输时是百分号编码（`/新增` → `/%E6%96%B0%E5%A2%9E`）。
**服务端必须解码**，否则枢言侧拿到的是编码串，`路径 等于 "/新增"` 永远不成立——
中文路由会静默失效（返回 404，但不报错）。

对「中文原生语言」来说这不是小事：**如果中文路由不能用，中文优先就只在源码层面成立**。
处理方式见 `服务.py` 的 `_path()`。

## 边界声明（如实说明）

| 维度 | 现状 |
|---|---|
| 网络模块 | **无内置网络模块**，需宿主适配层（本示例即如此） |
| HTTP 方法 | **路由只按路径分发，不区分方法** —— `GET /新增` 也会触发提交分支（返回 302）。生产应用需按方法细化，属应用层职责，非语言限制 |
| 并发 | 解释器单线程；本示例用宿主线程池（`ThreadingHTTPServer`） |
| 数据持久化 | 本示例用内存列表；可改用 `文件.写文本` 存文本，**重启即清空** |
| 数据库 | **无**，标准库不含任何数据库访问 |
| 模板引擎 | **无**，HTML 靠字符串拼接（对中小页面够用） |
| 安全性 | **无**表单转义 / CSRF / 限流。示例为演示用途，不可直接用于公网 |
| 部署 | 需 Python 环境（未提供独立可执行打包） |

> 上表不是「缺陷清单」，而是**边界声明**。把这些写清楚，与把能做的写清楚同样重要。

## 文件

| 文件 | 行数 | 职责 |
|---|---|---|
| `应用.sy` | 123 | 全部业务逻辑（枢言） |
| `服务.py` | 127 | 网络适配（宿主） |
| `自测.py` | 约 150 | 端到端自测（宿主，发真实 HTTP 请求） |

业务代码与适配代码的比例约为 **1:1** —— 这说明当前阶段，
做 Web 应用有相当一部分成本花在「补基础设施」上，而非写业务。
补充 `网络` 模块后，这个比例会显著改善。
