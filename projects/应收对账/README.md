# 应收对账与账龄分析系统

一个用枢言（`.sy`）写的**企业级多文件工程**，用于验证「中文原生语言能不能
扛住真实业务系统」。它不是玩具示例 —— 它按真实财务口径实现了应收单管理、
回款登记、信用管控与账龄报表。

## 为什么做这个工程

前面所有示例都是**单文件**、几十行的规模，无法回答两个关键问题：

1. **多文件工程**跑得起来吗？模块间的类型（结构体 / 枚举）传得过去吗？
2. **真实业务约束**（金额精度、中文表格对齐、状态流转、信用拦截）表达得出来吗？

本工程用**真实的企业需求**来回答。结论写在最后。

## 运行

```bash
sy 运行 projects/应收对账/主程序.sy
```

## 文件结构

| 文件 | 职责 | 依赖 |
|---|---|---|
| `领域模型.sy` | 类型中枢：3 个枚举、3 个结构体、构造辅助 | 无 |
| `账龄服务.sy` | 业务规则：日期差、账龄分桶、回款、信用检查 | `领域模型`、`数学` |
| `报表.sy` | 展示：金额格式化、中文对齐、明细与汇总表 | `账龄服务`、`领域模型`、`文本` |
| `主程序.sy` | 编排：把五段业务流程串起来 | 以上三者 |

依赖是**单向**的：`主程序 → 报表 → 账龄服务 → 领域模型`。
底层不知道上层存在 —— 换掉报表，业务逻辑一行都不用动。

## 业务规则（都有明确口径）

| 规则 | 口径 |
|---|---|
| 金额 | **一律整数分**，全程不做浮点运算（避免 `0.1 + 0.2` 类误差） |
| 信用管控 | 新单金额 + 客户现有应收 > 信用额度 ⇒ 拦截开单 |
| 回款 | 金额须 > 0 且 ≤ 未收余额；全额回款则单据转「已结清」 |
| 账龄 | 按逾期天数分四档：未到期 / 30 天内 / 60 天内 / 90 天以上 |
| 作废 | 已作废单据不进报表、不计信用、不允许回款 |
| 中文表格 | 列宽按**显示宽度**（汉字算 2 列），数字列右对齐 |

## 演示流程

`主程序.sy` 依次演示五段：

1. **客户建档** —— 3 家客户，各自信用额度与账期不同
2. **开具应收单** —— 含一次**信用拦截**（AR2026006 因超额度被拒）
3. **登记回款** —— 含一次**超额拦截**、一次**零额拦截**
4. **信用占用** —— 按客户统计应收占用与额度使用率
5. **账龄报表** —— 明细表 + 账龄汇总表，全部按中文列宽对齐

## 这个工程验证了什么

### 结论：业务层够用，缺的是基础设施

- **业务表达能力充足**：路由式流程、状态机、信用校验、分组汇总、
  中文报表 —— **全部用现有语法写出，没有为它新增任何语言特性**。
- **多文件工程可用**：类型（结构体 / 枚举）能跨模块传递，
  `引入 "模块"` 与 `引入 { 名字 } 从 "模块"` 两种口径都正常。
- **缺的是基础设施**，不是表达能力：没有网络 / HTTP 模块，
  所以 Web 类应用需要宿主薄适配层（见 `projects/留言板`）。

### 实测暴露并已修复的语言缺陷

本工程是**发现真缺陷最多**的一个工程 —— 因为它的用法足够「真实」：

| 缺陷 | 现象 | 修复 |
|---|---|---|
| **表达式语句静默丢弃** | 长表达式行首运算符续写被当成新语句，**整列数据消失且零报错** | 解析期报 `D2012`，提示「运算符挪到上一行行尾」 |
| **参数遮蔽内置模块** | 形参 `文本` 挡住模块 `文本`，报错指向调用处而非真因 | 定义处提醒 `W4001`；运行期补可行动提示 |
| **结构化提示被丢掉** | 提示写进了异常值，CLI 却一个字不显示（两处渲染各写一份） | 收敛为唯一渲染入口 `describe_error_value` |

其中第一条最危险：**结果错 + 无人察觉**。它印证了本项目的核心工程判断 ——
**静默丢弃比报错危险得多**。

## 可复现性

本工程随 `sy 检查 examples/*.sy projects/*/*.sy` 一起被自动检查，
`sy 检查` 必须对它**零错误、零警告**。这是「对外声明的数字必须有脚本能跑出来」
这一约定的具体落实。
