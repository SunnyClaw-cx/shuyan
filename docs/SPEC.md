## 0. 设计目标与非目标

### 0.1 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | **白话可编程**：能用接近自然汉语的句式写程序 | 存在「白话端口语」表面语法，且与形式语法共享同一 AST |
| G2 | **中文优先的词法**：中文关键字、中文标识符原生支持 | 词法层直接接受 CJK，而非事后转写 |
| G3 | **报错即教学**：错误信息必须说清「哪一行、什么错、怎么改」 | 所有诊断码 D1xxx 以下均含修复建议 |
| G4 | **语义确定性**：中文无空格带来的切分歧义必须被规则消除 | 三级字块裁决算法（见 §2.4），无回溯、无歧义 |
| G5 | **可移植自研**：不使用任何语言的源码、语法文件或生成器 | 纯标准库实现，无 ANTLR / 无第三方 |
| G6 | **函数是一等公民**：函数可赋值、可传参、可返回 | 标准库提供 `筛选` / `映射列表` / `归约` 等**高阶函数**，且能回调枢言函数 |
| G7 | **失败可定位**：一条语句出错**只报一条**，不级联 | 行级恐慌恢复（见 §8.5），丢弃本行剩余记号后跳到下一行 |

### 0.2 非目标（v0.1 / v0.2 明确不做）

- 不做宏系统、元编程。
- 不做泛型与类型类。类型以「窄 → 宽自由扩展」为原则（见 §5.4）。
- 不追求零开销抽象；当前性能目标是「可用」，不是「最快」。**当前实现是解释器**，没有字节码 VM、也没有 JIT（见 §10 路线图）。
- **类型系统是保守推断，不是 HM 类型推导、也不是 Rust 式借用检查**。只在「能推的地方」推 —— 推不出来就标为 `任意`，不做全程序推断，也不为了「看起来严格」而给出假保证（见 §5.4.1）。
- **没有 REPL、没有调试器、没有包管理器**（见 §10 路线图）。

### 0.3 与既有中文语言的关系声明

枢言的设计**独立完成**。参考的仅是**公开的、属于常识层面的语言设计问题**（如中文分词歧义、全角符号、UTF-8 处理），不复制任何既有中文编程语言的源码、关键字表、语法文件或编译器实现。具体而言：

- 关键字表为本项目自行拟定，以「汉语语义自然度 + 与算法关键字无碰撞」为准。
- 词法与语法算法为本项目自研（三级字块裁决、双语端口归一）。
- 不引入任何既有中文语言的兼容层。

## 1. 源码与字符编码

### 1.1 编码

源码文件一律 **UTF-8**（无 BOM 亦可，有 BOM 会被忽略）。行尾允许 `LF` / `CRLF`。

### 1.2 合法字符

| 类别 | 范围 | 说明 |
|---|---|---|
| 汉字标识符字符 | `U+4E00`–`U+9FFF`（CJK 统一表意文字）、`U+3400`–`U+4DBF`（扩展 A） | 可直接用于标识符 |
| 拉丁标识符字符 | `A-Z a-z 0-9 _` | 用于与外部库/FFI 对接 |
| 空白 | `U+0020`、`U+0009`、全角空格 `U+3000` | 归一化见 §1.3 |
| 换行 | `U+000A`（`U+000D` 被忽略） | |

### 1.3 全角/兼容字符归一化

**在词法阶段的最前一步**执行，映射表如下：

| 全角 | 半角 | 全角 | 半角 |
|---|---|---|---|
| `（` U+FF08 | `(` | `）` U+FF09 | `)` |
| `［` U+FF3B | `[` | `］` U+FF3D | `]` |
| `｛` U+FF5B | `{` | `｝` U+FF5D | `}` |
| `，` U+FF0C | `,` | `；` U+FF1B | `;` |
| `：` U+FF1A | `:` | `。` U+3002 | **`;`（语句结束）** |
| `、` U+3001 | **`,`（列表分隔）** | `＝` U+FF1D | `=` |
| `－` U+FF0D | `-` | `＊` U+FF0A | `*` |
| `／` U+FF0F | `/` | `％` U+FF05 | `%` |
| `＜` U+FF1C | `<` | `＞` U+FF1E | `>` |
| `！` U+FF01 | `!` | `？` U+FF1F | `?` |
| `＆` U+FF06 | `&` | `｜` U+FF5C | `\|` |
| `～` U+FF5E | `~` | `＾` U+FF3E | `^` |
| `＠` U+FF20 | `@` | `＃` U+FF03 | `#` |
| `＿` U+FF3F | `_` | `＄` U+FF04 | `$` |
| `　` U+3000 | 空格 | `＂` U+FF02 | `"` |
| `＇` U+FF07 | `'` | | |

> **设计要点**：中文输入法下 `（）` 与 `()` 混用是高频事故源。归一化在词法层完成，**不报错**——这属于「输入意图明确」的情形。
> **例外**：中文全角标点 `“”` `‘’` 会归一化为字符串定界符；`、` 归一化为逗号（列表分隔），`。` 归一化为成员访问符（`对象。属性`）。真正「输入意图不明」的是 `《》`（书名号）、`—`（破折号）、`…`（省略号），它们报 `D1004`。

### 1.4 关键字与标识符的粘连（核心难点）

中文没有词间空格，`定义年龄` 与 `定义 年龄` 必须等价。裁决算法见 §2.4，**这是枢言词法层的核心算法**。

## 2. 词法规则

### 2.1 记号（Token）种类

| 种类 | 说明 |
|---|---|
| `KEYWORD` | 语言关键字（中文/拉丁两套拼写，见 §2.3） |
| `IDENT` | 标识符（汉字串或拉丁串，或二者混合如 `订单_ID`） |
| `NUMBER` | 数值字面量（整数 / 小数 / 中文数词） |
| `STRING` | 字符串字面量（支持插值，见 §2.6） |
| `OP` | 运算符与标点 |
| `NEWLINE` | 逻辑换行（用于语句终止，见 §2.7） |
| `EOF` | 文件结束 |

### 2.2 空白与注释

```
行注释：  # 到这里行尾都是注释
        //  同上（拉丁写法）
块注释：  /* ... */     不支持嵌套
```

- 行注释从 `#` 或 `//` 起到行尾。
- 块注释不可嵌套；未闭合报 `D1003`。
- 注释不产生记号，但**保留其位置信息**，供格式化器还原。

### 2.3 关键字表

关键字分为**三类**，分类直接决定 §2.4 的切分规则。拉丁拼写为等价别名（便于键盘输入）。

#### A 类：引导词（后接表达式或标识符，**紧贴型**）

| 白话（口语） | 形式（书面） | 拉丁 | 语义 |
|---|---|---|---|
| `设` | `定义` | `let` | 变量声明（可变） |
| `令` | `常量` | `const` | 常量声明（不可变） |
| `若` | `如果` | `if` | 条件分支 |
| `遍历` | `对于` | `for` | 遍历 |
| `当` | `只要` | `while` | 条件循环 |
| `重复` | `循环` | `loop` | 计数/无限循环 |
| `返回` | `返回` | `return` | 返回 |
| `抛出` | `抛出` | `throw` | 抛出异常 |
| `引入` | `引入` | `use` | 导入模块 |
| `断言` | `断言` | `assert` | 断言 |
| `类型` | `类型` | `type` | 类型别名声明 |

#### B 类：块与结构词（**独立型**，必须自成一块）

| 白话 | 形式 | 拉丁 | 语义 |
|---|---|---|---|
| `否则若` | `否则如果` | `elif` | 否则如果 |
| `否则` | `否则` | `else` | 否则 |

| `捕获` | `捕获` | `catch` | 捕获分支 |
| `最终` | `最终` | `finally` | 收尾块 |
| `真` | `真` | `true` | 布尔真 |
| `假` | `假` | `false` | 布尔假 |
| `空` | `空` | `nil` | 空值 |
| `且` | `且` | `and` | 逻辑与 |
| `或` | `或` | `or` | 逻辑或 |
| `非` | `非` | `not` | 逻辑非 |

#### C 类：联结与介词（**紧贴型后缀**）

| 白话 | 形式 | 拉丁 | 语义 |
|---|---|---|---|
| `是` | `是` | `is` | 赋值（白话句式）；相等（表达式中） |
| `把` | `把` | — | 赋值目标引导（白话句式） |
| `从` | `从` | `from` | 循环起点 / 导入来源 |
| `到` | `到` | `to` | 循环终点 |

| `中` | `中` | `in` | 成员判断 / 遍历来源 |
| `当…时` | — | — | 条件循环的收尾词（白话） |
| `成立` | — | — | 条件循环的收尾词（形式） |
| `则` | `则` | `then` | 分支收尾（可选） |
| `结束` | `结束` | `end` | 块结束 |
| `比如` | `比如` | `eg` | 函数用法示例（惰性块） |

> **注意**：`是` 与 `中` 是**双身份词**——既作 C 类联结词，也作表达式运算符。裁决见 §2.4 与 §4.3。

### 2.4 三级字块裁决算法（核心）

**问题**：源码 `定义年龄=20` 中，`定义年龄` 必须切成 `定义` + `年龄`；而 `数据中台` 必须整体作为一个标识符。

**定义**：把一段被空白、运算符、数字、拉丁字符或行尾隔开的**最大连续汉字段**称为一个字块（Han Block）。
例如 `定义年龄=20` 的字块是 `定义年龄`；`若 年龄 不小于 18` 有三个字块：`若`、`年龄`、`不小于`。

**算法（单趟贪心最长匹配，无回溯）**：

```
对字块 H 执行 切分(H)：
  第 0 步  若 H 整体命中关键字表（任意类别）    → 输出 KEYWORD(H)，结束
  第 0.5步 若 H 以中文数词开头 →  取最长数词前缀 N
             · N 覆盖整个 H          → 输出 NUMBER(N)，结束
             · N 后仍有剩余          → 输出 NUMBER(N)，再 切分(剩余)，结束
  第 1 步  A 类前缀：取最长的、是 H 前缀的 A 类关键字 K
             若存在 → 输出 KEYWORD(K)，再 切分(H 去掉 K 的部分)，结束
  第 2 步  C 类后缀：取最长的、是 H 后缀的 C 类关键字 K
             · K ∈ C_MULTI              → 切
             · K ∈ C_SINGLE 且 len(H)-len(K) ≥ 2 → 切
             若切 → 先 切分(H 去掉 K 的部分)，再输出 KEYWORD(K)，结束
  第 3 步  C 类中缀（**仅 C_MULTI 参与**）：取 H 中最长的非首非尾 C_MULTI 关键字 K
             若存在 → 切分(左部) + KEYWORD(K) + 切分(右部)，结束
  第 4 步  软助词：若 H 整体 ∈ FILLER_EXACT → 不输出记号，结束
             若 H 以 FILLER_SOFT 结尾且剩余非空 → 切分(剩余)，结束
  第 5 步  否则 → 输出 IDENT(H)，结束
```

**三通道的必要性**：中文联结词有的出现在**块首**（`定义年龄` 的 `定义`），有的出现在**块尾**（`年龄是` 的 `是`），有的出现在**块中**（`名单中每个名字` 的 `中的每个`）。只用前缀匹配会漏掉后两类，只用后缀匹配会漏掉第一类。故必须三通道齐备。

**核心约束（正是它们消除了歧义）**：

| 约束 | 防住的错误 |
|---|---|
| C 类单字词（是/为/叫/从/到/中/里）**不参与中缀**切分 | `数据中台` → 不得裂成 `数据`+`中`+`台`；`期中成绩` 同理 |
| C 类单字词作后缀时，要求「前缀部分长 ≥ 2」 | `规则` 之类的短块不被误切 |
| 软助词 / 填充词**仅整体命中**才剥离 | `规则` → 不得削成 `规`；`成立` 只有独立成块才作收尾词 |
| 拉丁关键字**不参与**汉字粘连切分 | `订单_ID` 不受影响 |
| 数词切分**先于**关键字切分 | `三次` → `3`+`次`，而非 `三`+`次` 或整块 |

**样例对照**：

| 源码字块 | 切分 | 依据 |
|---|---|---|
| `定义年龄` | `定义` `年龄` | 第 1 步 A 类前缀 |
| `苹果个数` | `苹果个数` | 第 5 步 |
| `否则若` | `否则若` | 第 0 步整体命中 |
| `年龄是` | `年龄` `是` | 第 2 步 C 类后缀（len 3-1=2 ≥ 2） |
| `年龄不小于` | `年龄` `不小于` | 第 2 步 C_MULTI 后缀 |
| `名单中每个名字` | `名单` `中` + `每个` `名字` | 第 2 步（`中`）+ 第 3 步中缀（`每个`） |
| `数据中台` | `数据中台` | 第 5 步（C_SINGLE 不参与中缀） |
| `期中成绩` | `期中成绩` | 第 5 步 |
| `规则` | `规则` | 第 5 步（软助词仅整体命中） |
| `无线网络` | `无线网络` | 第 5 步 |
| `三次` | `3` `次` | 第 0.5 步数词优先 |
| `一百二十` | `120` | 第 0.5 步 |
| `值等于` | `值` `等于` | 第 2 步 C_MULTI 后缀 |
| `如果条件成立` | `如果` `条件成立` | 第 1 步前缀；软助词不生效（非整体命中） |
| `返回结果` | `返回` `结果` | 第 1 步 |

> **歧义消除保证**：算法为**确定性单趟**，不做回溯，不依赖后续记号。同一字块 ⇒ 切分结果唯一。
> **工程提示**：若确实需要「以关键字开头的标识符」，用反引号形式 `` `定义年龄` ``（§2.5）。
> **单位词 `次`**：`次` 长度为 1，不在 C_MULTI 中，仅能作为**独立块**切出（`重复 10 次`）或由数词规则切出（`重复三次`）。

**已知的合法切分与逃生舱（实测得出）**：

单字联结词作后缀时，规则允许在**长度 ≥ 2 的前缀**后切分（第 2 步），
因此下列常见词会被切开：

| 源码字块 | 切分结果 | 说明 |
|---|---|---|
| `进行中` | `进行` + `中` | `中` 作后缀，前缀 `进行` 长 2 |
| `处理中` | `处理` + `中` | 同上 |
| `审核中` | `审核` + `中` | 同上 |
| `计划里` | `计划` + `里` | `里` 同属 C_SINGLE |

这是**规则为了换取确定性而付出的代价**：要让 `数据中台` 不被切开，
`中` 就不能无条件地参与一切切分位置；而一旦允许「前缀长 ≥ 2 就切」，
`进行中` 这类词就必然被切开。

**中文数词优先于标识符（已知歧义，v0.3 记录）**：

§2.5 说「汉字序列可作标识符」，§2.6 说「中文数词是数字字面量」——
二者对 `一百二十` 给出**不同答案**。实现的裁决是**数词优先**：

```shuyan
定义 一百二十 = 5      # ✗ D2002「这里应该是一个变量名」
输出(一百二十)          # 视为数字 120
```

这是**可预测、可解释**的行为，属已知边界而非缺陷（`tools/probe_extreme.py`
的可复现用例）。需要中文数词形态的标识符时，用反引号逃生舱：

```shuyan
定义 `一百二十` = 5    # ✓ 整体作为标识符
输出(`一百二十`)        # 打印：5
```

理由：把 `一百二十` 判为数字是**日常使用频率远高**的一面，
且数词识别是确定性的（不依赖上下文猜测）。若反过来让标识符优先，
`输出(一百二十)` 就会变成一个未定义的变量名 —— 那更常错。

**嵌套深度上限（v0.3 新增，实现约束）**：

递归下降解析器每进入一层嵌套就多消耗数层宿主调用栈。故实现设
**统一的嵌套深度上限 180**（表达式与语句块共用），超限报 `D2013`
并给出「拆成中间变量 / 函数」的可行动建议，**不硬撑到宿主栈溢出**。

| 形态 | 宿主栈边界（实测） | 每层消耗 |
|---|---|---|
| 括号 `(((...)))` | 约 320 层 | ≈ 3.1 帧 |
| 列表 `[[[...]]]` | 约 240 层 | ≈ 4.2 帧 |
| `如果` 块嵌套 | 约 240 层 | ≈ 4.2 帧 |

上限取 180 = 最紧形态（240）× 75%，留 25% 余量。这是**实现约束**，
不是语言限制：任何真实程序都不需要 180 层嵌套。另有兜底 ——
万一有未覆盖的形态漏网，编译边界也会把 `RecursionError` 转成
同一条 `D2013` 诊断，**绝不把宿主堆栈抛给用户**。

**逃生舱（唯一手段）**：用反引号把整个词声明的标识符形式写出：

```shuyan
类型 状态 = { 待处理, `进行中`, 已完成 }
输出(状态.`进行中`)          # 打印：状态.进行中
```

反引号在**声明端与访问端语义一致**，且规范化后的成员名**不含反引号**
（`状态.进行中` 而非 ``状态.`进行中` ``），因此打印、比较、报错提示都干净。

> 本项目**不采用**词频统计或词典来「猜」哪些词该整体保留 —— 那会引入
> 不可预测性，与「规则确定、无回溯」的核心承诺冲突。
> 需要整体保留时，一律由用户用反引号**显式声明意图**。

### 2.5 标识符规则

**常规标识符**：

```
汉字标识符 := [汉字]([汉字] | [数字] | [_])*
拉丁标识符 := [A-Za-z_][A-Za-z0-9_]*
混合标识符 := 汉字/拉丁 段之间用 _ 连接，如 订单_ID、user_编号
```

**反引号标识符**（逃生舱，用于规避关键字碰撞）：

```
`定义年龄`     ← 整体作为标识符，内部可含关键字
```

**保留：不可用作标识符的词**：§2.3 全部关键字（反引号形式除外）。

**禁忌**：标识符不得以数字开头；不得含空格（中文空格也不行）。

### 2.6 字面量

#### 2.6.1 数值

```
整数：  123       1_000_000     0x1F    0b1010
小数：  3.14      1.5e3         1e-6
中文数：三        一百二十      二百五十      十五      20万
```

- 下划线 `_` 可作千位分隔符，词法层剔除。
- 十六进制 `0x`、二进制 `0b` 前缀。`0o`/`0O` 前缀识别但**报 `D1005`**（v0.1 未实装八进制），提示改用十进制或十六进制。
- **不支持**前导零形式（`0777` 报 `D1005`）。
- **中文数词字面量**：支持 `零一二三四五六七八九十百千万亿` 与 `两`。规则：
  - 单字：`一`…`九`、`十`、`两` ⇒ 对应 1…9、10、2。
  - 组合：按「单位递降」规则解析，`一百二十` = 120，`十五` = 15，`三百零五` = 305。
  - 尾随缩写单位：`3万`、`20万`、`1.5亿`、`10兆`（`万=1e4 亿=1e8 兆=1e12`），结果为对应倍数（整数或小数）。
  - `零` 仅作占位，值为 0。裸 `零` 是合法的 0。
  - 解析失败（如 `十百`、`万万`）报 `D1005`，并给出「请改写成阿拉伯数字」的建议。
  - 中文数词**不与标识符混用**：`三只苹果` 会被切为标识符（因为整块含非数词汉字），不会静默变成 `3`。

#### 2.6.2 字符串

```
"普通字符串"
'单引号字符串'
"""跨行
字符串"""
`插值字符串：你好，{名字}，年龄 {年龄+1}`
```

- 双引号 / 单引号字符串**不插值**，转义遵循与 C 一致的最小集：`\n \t \\ \" \' \r \0`，另加 `\{`（插值串中表示字面 `{`）。
- **反引号字符串插值**：`{表达式}` 处插入求值结果；`{{` 表示字面 `{`。
- 全角引号 `“”` `‘’` 在 §1.3 已归一化为半角定界符。
- 字符串内部**一律 UTF-8**，索引与长度按**字符（码点）**计，不按字节计——这是中文语言的基本要求。

#### 2.6.3 布尔与空

`真` / `假` / `空`（拉丁：`true` / `false` / `nil`）。

### 2.7 语句终止与块结构

- **语句终止**：换行（`NEWLINE`）或 `;`（`；` 归一化后）。同一行内多条语句用 `;` 分隔。
- **续行**：行尾为 `+ - * / % ( [ , 且 或 是` 之一时，**不产生** NEWLINE（自动续行）。未闭合的 `(` `[` `{` 内部也自动忽略换行。
  - **续行以「行尾」为准，行首运算符不接续上一行。** 行首的 `+` `-` 等会被当作
    新语句的开始（一元运算符），使上一行的拼接断裂。若该表达式的值没有任何
    副作用，触发语法错误 **`D2012`**（「这条语句算出结果就丢掉了」），
    并提示把运算符移到上一行行尾或用圆括号括起来。
  - 之所以**报错而非自动续行**：把行首运算符接回上一行会改变语言语义
    （`-x` 独立成句将不再合法），且违背「规则确定」的承诺。
  - 实测来源：企业级工程 `projects/应收对账/报表.sy` 的报表渲染 —— 行首
    `+` 使整列数据被静默丢弃（左操作数为数字时连类型错误都不报）。
- **句读逗号（中文特有）**：`，`（归一化为 `,`）在**语句层**（不在括号 / 列表 / 参数列表内）
  视为**句读停顿**，不产生语义，被解析器忽略。白话写法依赖此规则成立，例如
  `若 年龄 不小于 18，那么` 中的 `，` 只是停顿。在括号 / 列表 / 映射 / 参数列表内，
  `,` 仍是**分隔符**。
- **块**：以 `结束` 结尾，或用 `{ }`（缩进不参与语法，v0.1 不做缩进敏感）。

```
# 形式写法
如果 年龄 >= 18 则
    输出("成年")
否则
    输出("未成年")
结束

# 白话写法（同一 AST）
若 年龄 不小于 18，那么
    说一声"成年"
否则的话
    说一声"未成年"
完
```

> v0.1 中，白话端口 B 类收尾词、A 类前置词均已在 §2.3 给出；`那么`/`完`/`否则的话` 属于白话端**软收尾词**（可省略），解析器按可选处理。规范正式收尾词为 `结束`，白话收尾词为 `完`。

### 2.8 词法错误码

| 码 | 触发 |
|---|---|
| `D1001` | 非法字符 |
| `D1002` | 字符串未闭合 |
| `D1003` | 块注释未闭合 |
| `D1004` | 意图不明的全角标点（`、` `《》` `—` `…`） |
| `D1005` | 非法数值字面量（如 `0777`、`1.2.3`） |
| `D1006` | 标识符以数字开头 |
| `D1007` | 插值表达式未闭合 |

## 3. 语法（文法）

记号：`A?` 可选，`A*` 零或多次，`A+` 一次或多次，`|` 择一，`«»` 语义动作说明。

### 3.1 程序结构

```
程序        := 语句* EOF
语句        := 变量声明 | 常量声明 | 赋值 | 表达式语句 | 分支 | 循环
             | 函数定义 | 返回 | 抛出 | 尝试 | 引入 | 类型声明 | 断言 | 块
块          := 「{」 语句* 「}」 | 语句* 「结束」(白话: 「完」)
```

### 3.2 变量与常量声明

```
变量声明    := 定义 标识符 (: 类型)? (= 表达式)?
常量声明    := 常量 标识符 (: 类型)? = 表达式
白话: 设 名字 是 表达式        /  设 名字 为 表达式
      令 名字 是 表达式  (常量)
```

`定义 甲` 合法（声明为 `空`）。`常量` 必须带初值，否则 `D3001`。

### 3.3 赋值

```
赋值        := 左值 赋值算符 表达式
赋值算符    := = | += | -= | *= | /= | %= | 是
白话: 把 表达式 给 名字     /   名字 是 表达式
```

### 3.4 分支

```
分支 := 如果 表达式 (则)? 块
        (否则如果 表达式 块)*
        (否则 块)?
        结束
白话 := 若 表达式 (那么)? 块
        (否则若 表达式 块)*
        (否则的话? 块)?
        完
```

`则` / `那么` 为可选分隔词；省略时需块以换行开始。

### 3.5 循环

```
条件循环 := 当 表达式 (成立)? 块 结束
白话     := 只要 表达式 (的话)? 块 完
           | 当 条件 的时候 块 完

计数循环 := 重复 N 次 块 结束
           | 重复 标识符 从 A 到 B (步长 S)? 块 结束
遍历循环 := 遍历 标识符 中? 表达式 块 结束
白话     := 遍历 名单 中的 每个 名字 块 完

跳出/继续 := 跳出 | 继续
```

`重复 3 次`：`N` 为表达式，求值为非负整数。

**区间闭合性（易错点，明确声明）**：
- `重复 甲 从 A 到 B`：**包含** A 与 B（自然语言语义，闭区间）。
- `范围(A, B)`：**不包含** B（半开区间，与主流语言一致，便于 `范围(长度(列表))` 遍历）。
- `A .. B`（区间表达式）：**包含** B（闭区间，与 `从…到…` 同口径）。

> 三种区间写法刻意不一致，是为了各自贴合其使用场景；规范在此**显式列出**，
> 不留模糊地带。若需统一感知，建议只用其中一种。

### 3.6 函数

```
函数定义 := 请 标识符 「(」 参数列表? 「)」 (返回 类型)? 块 结束
白话     := 定义 一个 函数 叫 名字 参数是 (a, b) 做的事 块 完
           | 让 名字 来做 块 完

参数列表 := 参数 (「,」 参数)*
参数     := 标识符 (: 类型)? (= 默认值)?
```

- **默认参数**：可有多个，但必须位于无默认参数之后，否则 `D3002`。
- **可变参数**：`... 名字` 收尾，收集为列表，最多一个且必须收尾。
- **重载**：v0.1 **不支持**（按 `D3003` 明确报错，提示改用可选参数或分派判断）。← 诚实排除，不假装支持。

### 3.7 返回与异常

```
返回     := 返回 表达式?
抛出     := 抛出 表达式
尝试     := 试 块 (捕获 标识符? 块)* (最终 块)? 结束
```

白话：`试试看 块 出错了 块 最后 块 完`。

异常值可以是**任意值**（不限字符串）。未被 `捕获` 的异常向上传播；到达顶层则程序以码 1 退出并打印中文诊断。

### 3.8 引入

```
引入 := 引入 字符串
      | 引入 { 标识符 (「,」标识符)* } 从 字符串
```

v0.1 支持导入**本机枢言模块（.sy）**与**注册的内置模块**（`文本` `列表` `映射` `数学` `时间` `文件` `系统` `正则` `编码` `随机` `加密`）。

#### 3.8.1 多文件工程口径（v0.2 明确）

**两种引入形式产出两种不同的名字绑定 —— 这是刻意的，不是疏漏。**

| 形式 | 绑定方式 | 使用方式 |
|---|---|---|
| `引入 "工具"` | **命名空间绑定**：模块整体作为一个命名空间绑定到模块名 | `工具.平方(3)` |
| `引入 { 平方 } 从 "工具"` | **按名直接绑定**：只有列出的名字进入当前作用域 | `平方(3)` |

三条配套约定：

1. **路径解析基准 = 主脚本所在目录**。`引入 "工具"` 解析为「主脚本目录下的
   `工具.sy`」。**不以当前工作目录为准** —— 否则同一程序在不同目录下运行
   会引入到不同文件，行为不可复现。
2. **候选路径与导出规则在编译期与运行期必须同口径**。语义分析器与解释器
   走**同一套**候选路径与导出规则；任何一方单独放宽都会造成「编译通过、
   运行时找不到」或反之。这是项目铁律「同一语义两处实现必然分叉」在引入
   机制上的落实。
3. **循环引入防护**：正在加载的模块集合被记录，重入即报错，不做静默忽略
   （静默忽略会让「导出为空」这种症状极难定位）。

4. **类型定义参与导出**：模块中定义的 `类型` 在整模块引入时并入命名空间，
   在按名引入时可被点名导出 —— 跨模块使用类型与使用函数一致。

### 3.9 类型声明（别名 / 结构体 / 枚举）

```
类型声明   := 类型 标识符 "=" 类型定义
类型定义   := 别名定义 | 结构体定义 | 枚举定义
别名定义   := 类型表达式
类型表达式 := 基础类型 | 标识符 | "[" 类型表达式 "]"
基础类型   := 整数 | 小数 | 文本 | 布尔 | 空 | 列表 | 映射 | 函数 | 任意

结构体定义 := "{" 字段 ("," 字段)* "}"
字段       := 标识符 ":" 类型表达式

枚举定义   := "{" 成员 ("," 成员)* "}"
成员       := 标识符
```

#### 3.9.1 三种写法的判定

| 花括号内容 | 判定 |
|---|---|
| 存在**含 `:` 的条目** | **结构体** |
| **全部条目都不含 `:`** | **枚举** |
| 两种条目混用 | 报 `D3019` |
| 空花括号 `{}` | 报 `D3019` |

判定**单趟完成、无回溯**：只需在读到 `}` 前记录「是否见过 `:`」。

#### 3.9.2 结构体

```shuyan
类型 点 = { 横: 整数, 纵: 整数 }

定义 甲 = 点(横 是 3, 纵 是 4)
输出(甲.横)          # 3
甲.纵 = 5            # 字段可写
输出(甲)             # 点{横: 3, 纵: 5}
```

- **构造**用调用语法：`类型名(字段 是 值, ...)`。字段用**具名参数**给出，顺序无关。
- **字段访问**用 `.`：`甲.横`。**访问不存在的字段报 `D3018`**（列出可用字段与拼写候选），不静默返回空。
- **字段可写**：`甲.纵 = 5`。写入不存在字段报 `D3018`。
- **构造时字段校验**：缺字段、多字段、未知字段、字段类型不符都报 `D3017`。
- 结构体**值相等**按字段逐个比较（同类型同字段名同值）。

#### 3.9.3 枚举

```shuyan
类型 星期 = { 一, 二, 三, 四, 五, 六, 日 }

定义 今天 = 星期.三
输出(今天)            # 星期.三
输出(今天.序号)       # 3      （成员序号，从 1 起）
输出(今天.名称)       # 三
若 今天 是 星期.三 则
    输出("今天周三")
结束
```

- **成员访问**用 `.`：`星期.三`。不存在的成员报 `D3019`（列出全部成员）。
- **成员名按源码原文匹配**——`星期.一` 的 `一` 在词法上是中文数词，
  但枚举成员名一律取**记号原文**，不做数词归一。声明与访问两侧同口径，
  因此 `类型 星期 = { 一, 二 }` 与 `星期.一` 能正确对应。
  （写 `星期.1` 不匹配成员 `一`，报 `D3019`。）
- **序号从 1 起**（枚举语义是「第几个」，中文语境下 `星期.一` 是第 1 个）。
- 枚举值**相等**按「同类型且同成员」比较；**不参与算术**。

#### 3.9.4 别名

```shuyan
类型 编号 = 整数
类型 名字表 = [文本]
```

别名只做重命名，**不产生新类型**（与 `编号` 的赋值检查等同 `整数`）。

#### 3.9.5 与映射类型的关系

v0.1 草案曾用 `{ 文本: 整数 }` 表示「键为文本、值为整数的映射」
（已从本节移除）。**该写法从未实现**（仅存了定义字符串，无任何语义），
且与结构体语法直接冲突，故正式取消。

映射类型统一用 `映射` 关键字：

```shuyan
定义 成绩表: 映射 = {"语文": 90, "数学": 95}
```

参数化映射（`{文本: 整数}` 这类泛型写法）属泛型范畴，**v0.1/v0.2 明确不做**，
见 §0.2 非目标；需要时由运行期动态检查承担。

### 3.10 块语法与 `结束` 配对

`结束` 可写成 `结束` / `end` / `完`。复合语句的 `结束` 数必须与开启数一致，否则 `D2009`（并给出「第几行的块未闭合」）。

## 4. 表达式与运算符

### 4.1 优先级表（自低到高）

| 级 | 运算符（白话/形式） | 结合性 | 说明 |
|---|---|---|---|
| 1 | `是`（赋值） | 右 | 语句层，非表达式 |
| 2 | `或` | 左 | 短路 |
| 3 | `且` | 左 | 短路 |
| 4 | `非` | 右（前缀） | |
| 5 | `是` / `不是` / `等于` / `不等于` / `大于` / `小于` / `不小于` / `不大于` / `属于` / `不属于` | 左（**链式禁止**） | 比较，返回 `布尔` |
| 6 | `在…中` / `中` | 左 | 成员测试 |
| 7 | `..` | 左 | 区间（生成列表） |
| 8 | `+` `-` | 左 | 加减 / 文本拼接 |
| 9 | `*` `/` `%` | 左 | |
| 10 | `^` | 右 | 幂 |
| 11 | 一元 `-` `+` `非` | 右 | |
| 12 | `调` `(` `[` `.` | 左 | 调用、索引、取成员 |
| 13 | 字面量、标识符、`(` 表达式 `)` | — | |

**比较链式禁止**：`1 < 2 < 3` 报 `D3010`，要求写 `1 < 2 且 2 < 3`。理由：三段比较在多数语言中是陷阱，枢言选择显式化。

### 4.2 运算符别名对照

| 形式 | 白话 | 拉丁 |
|---|---|---|
| `==` | `等于` / `是` | `==` |
| `!=` | `不等于` / `不是` | `!=` |
| `>` | `大于` | `>` |
| `<` | `小于` | `<` |
| `>=` | `不小于` / `至少` | `>=` |
| `<=` | `不大于` / `至多` | `<=` |
| `+` | `加上` | `+` |
| `-` | `减去` | `-` |
| `*` | `乘以` | `*` |
| `/` | `除以` | `/` |
| `%` | `取余` | `%` |
| `^` | —（见下注） | `**` |

> **关于「的…次方」**：早期草案曾计划把 `2 的 10 次方` 作为 `^` 的白话写法。
> 实测后**否决**：中文的「的」字出现频率极高（`我的名字`、`系统的状态`），
> 把它定为运算符会制造大量歧义，且需要解析器回溯——这与本语言「词法单趟、
> 无回溯」的核心承诺冲突。
> **替代方案**：幂运算用 `^`，或调用内置函数 `次方(底, 指数)`。
> 白话写法示例：`面积 是 次方(边长, 2)`。
> 这类「看起来自然但代价过高」的写法，规范宁可放弃，也不留下模糊地带。

> 白话算式示例：`面积 是 长 乘以 宽`、`结果 是 次方(2, 10)`。

### 4.3 `是` 的双身份消歧

- **语句首位置**：`是` 视为赋值（`甲 是 1`）⇒ 实为「左值 `是` 表达式」形式，见 §3.3。
- **表达式中间位置**（已有左操作数且右侧仍有操作数）：视为相等比较。
- **判定规则**：在语句层扫描，若一个语句形如 `IDENT (是) 表达式` 且该语句**不含其他比较运算符**，判为赋值；否则 `是` 为相等运算符。解析器实现为「先尝试赋值形（无回溯的形态判断：头部 token 为 IDENT/成员访问，第二个 token 为 `是`）」。

#### 4.3.1 与具名参数的冲突（实测得出，规范明确记载）

枢言的**具名参数**写作 `名字 是 值`（§3.6）。这与 `是` 的相等比较身份在
**同一位置**上冲突：

```shuyan
输出(甲 是 5)          # 解析为一项**具名参数**「甲 = 5」，不是比较！
输出(甲 等于 5)        # 比较，返回 布尔
```

**规范选择**：在**参数列表内部**，`标识符 是 值` 一律判为**具名参数**
（与用户函数的具名绑定一致，也与结构体构造一致）。这是确定性规则，
**不需要回溯**。

**代价是被显式化、而非被静默吞掉**：

| 情形 | 枢言行为 |
|---|---|
| 内置函数收到具名参数 | 报 `D3007`：「内置函数不支持具名参数，参数 X 会被忽略」 |
| 用户函数收到未知具名参数 | 报 `D3007`：「没有名为 X 的参数」+ 拼写候选 |
| 结构体构造的具名参数 | 正常语义（这是它的**唯一**写法） |

> 早期实现里，`输出(甲 是 5)` **既不输出也不报错**——静默丢弃。
> 这与本规范 §8.2「静默丢弃比报错危险」直接冲突，故增设守卫。
> 代价是：白话端写比较必须用 `等于`，不能用 `是`。
> 这是一次有意的取舍：**明确的错，好过安静的错**。

### 4.4 `是` 在参数内的写法建议

| 想表达 | 写法 |
|---|---|
| 相等比较 | `甲 等于 5`（推荐）；单独成句时 `甲 是 5` 也可 |
| 具名参数 | `甲 是 5`，仅限**用户函数**与**结构体构造** |
| 赋值 | `甲 是 5`，仅限语句首、且左侧是变量 |

三者位置不同、语义不同，规则均为**单趟可判**。

### 4.5 真值规则（truthiness）

条件位置（`如果`/`当`/`重复`/`且`/`或`/`非`）按下列规则判定：

**假值**：`假`、`空`、`0`、`0.0`、`""`（空文本）、`[]`（空列表）、`{}`（空映射）。
**真值**：除上述之外的一切值（含 `"0"`、`0.0000001`、`[0]`、非空文本含空白）。

> 选此规则而非「仅布尔可作条件」的理由：中文程序员的直觉更接近自然语言判断
> ——「有名字就……」，不宜强制写 `长度(名字) > 0`。代价是需明确「假值表」，
> 规范已完整列举，不留歧义。

### 4.6 相等比较的语义

- 数值：`1 == 1.0` 为**真**（跨整型/浮点比较按数值）。
- 文本：逐码点比较。
- 布尔：仅与布尔相等；`真 == 1` 为**假**（布尔不隐式转数值——避免 `0/1` 混乱）。
- `空`：`空 == 空` 为真；`空` 与任何其他值相等比较为假。
- 列表/映射：**按值比较**（结构相等），递归比较元素；映射忽略键顺序。
- 函数：按**引用**比较。

### 4.7 逻辑运算的返回值

`且` 与 `或` 为**短路**并返回**操作数本身**（而非强制转布尔）：
`甲 且 乙` 在 `甲` 为假值时返回 `甲`，否则返回 `乙`；`甲 或 乙` 在 `甲` 为真值时返回 `甲`。
这允许 `名字 或 "匿名"` 之类的惯用写法。

| 现象 | 裁决 |
|---|---|
| `1 .. 5` vs `1. .5` | `..` 优先匹配为区间运算符；`1..5` 亦合法（数字后紧跟 `..` 结束数字） |
| `甲 是 乙 是 丙` | 赋值右结合 → 等价 `甲 是 (乙 是 丙)`；但若 `乙` 为已定义且类型不可比较，语义层报 `D3004` |
| `非 甲 且 乙` | 优先级：`(非 甲) 且 乙` |
| `-3^2` | `-(3^2) = -9`（幂高于一元负，与数学惯例一致） |
| `文本+数字` | 若一侧为文本，另一侧**隐式转文本**再拼接，不报错（见 §5.4 扩展规则） |

## 5. 类型系统

### 5.1 基础类型

| 枢言名 | 拉丁 | 说明 |
|---|---|---|
| `整数` | `int` | 64 位有符号 |
| `小数` | `float` | IEEE 754 双精度 |
| `文本` | `text` | UTF-8 不可变字符串 |
| `布尔` | `bool` | |
| `空` | `nil` | 空值类型 |
| `列表` | `list` | 有序可变序列 |
| `映射` | `map` | 键值对，键须可哈希 |
| `函数` | `fn` | 一等公民，支持闭包 |
| `任意` | `any` | 动态类型上界 |

**复合类型**（由 `类型` 声明，见 §3.9）：

| 类别 | 类型名 | 值表示 |
|---|---|---|
| 结构体 | 声明时的标识符（如 `点`） | 具名字段集合，字段可读写 |
| 枚举 | 声明时的标识符（如 `星期`） | 具名成员之一，成员不可变 |

结构体与枚举**不参与隐式宽化**：只有 `任意` 能接收它们。
把结构体赋给 `整数` 之类的声明会得到 `D3004` 并指出两侧具体类型名。

### 5.2 复合类型字面量

```
[1, 2, 3]                      列表
{"甲": 1, "乙": 2}              映射
[1, "二", 真]                  ← 混合列表合法，元素类型为 任意
```

### 5.3 类型标注

变量、参数、返回均可标注：`定义 年龄: 整数 = 20`。省略则**推断**。

### 5.4 类型兼容规则（枢言的取舍）

v0.1 **不采用**严格子类型，采用如下**实用兼容表**：

| 源 → 目标 | 整数 | 小数 | 文本 | 布尔 | 空 | 列表 | 映射 |
|---|---|---|---|---|---|---|---|
| 整数 | ✔ | ✔（宽化） | ✔（隐式转文本） | ✘ | ✘ | ✘ | ✘ |
| 小数 | ✘（须显式取整） | ✔ | ✔ | ✘ | ✘ | ✘ | ✘ |
| 文本 | ✘ | ✘ | ✔ | ✘ | ✘ | ✘ | ✘ |
| 布尔 | ✘ | ✘ | ✔ | ✔ | ✘ | ✘ | ✘ |
| 空 | ✘ | ✘ | ✘ | ✘ | ✔ | ✘ | ✘ |
| 任何 | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |

- **整数 → 文本** 与 **布尔 → 文本** 允许隐式（拼接场景高频，拒绝会造成大量噪音）。
- **文本 → 整数** 禁止隐式，须用 `整(文本)`，失败抛异常。
- **空** 不参与任何隐式转换；比较 `甲 是 空` 合法（相等比较豁免）。
- **任意** 到具体类型为**运行时动态检查**。

#### 5.4.1 推断能力边界（**明确声明，避免过度期待**）

枢言的类型检查是**保守推断**，刻意不做全程序推导。理由是：中文标识符没有大小写、没有类型后缀，若强行做侵入式推断，误报率会高到用户直接关掉检查 —— 那比「少查一点」更糟。

| 能推断的 | 具体表现 |
|---|---|
| 字面量类型 | `1` → 整数，`"甲"` → 文本，`[1]` → 列表，`{甲: 1}` → 映射 |
| 变量声明类型 | 有标注用标注，无标注由初始值定 |
| 算术与比较结果 | 算术按操作数定，比较恒为布尔 |
| 内置函数返回值 | 由 `CORE_SIGNATURES` / `MODULE_SIGNATURES` 的签名表给出 |
| 用户函数返回值 | 有 `返回类型` 标注用标注；否则按函数体内 `返回` 语句的**共同类型**收敛，收敛失败则为 `任意` |
| 结构体 / 枚举成员 | 由类型声明给出 |

| **推不出的**（一律落为 `任意`，不做假保证） |
|---|
| 高阶函数的回调返回值 —— 第 2 个参数是函数，其返回类型不在静态可知范围 |
| 映射取值 `映射[键]` 的元素类型 |
| 命名空间模块成员若未被 `引入` 声明 |
| 递归函数的返回类型（收敛可能不终止） |

> **不做的事**：不做 Hindley–Milner 式统一、不做泛型实例化、不做借用/生命周期检查、不做跨函数副作用分析。这些都在路线图（§10）中，当前明确**不支持**。

### 5.5 作用域

| 作用域 | 引入方式 | 可见性 |
|---|---|---|
| 全局 | 顶层声明 | 全程序（含函数内，但**只读**：函数内赋值同名变量会创建局部变量，须 `全局 名字 = ...` 显式声明修改全局） |
| 函数 | 参数、函数体 `定义` | 函数体内及其嵌套块 |
| 块 | `{ }` / 分支 / 循环体 | 仅块内 |
| 闭包 | 函数捕获外层变量 | 捕获**按引用**（可变） |

**遮蔽（shadowing）**：允许内层同名，但触发 **警告 `W4001`**（可能非本意）。

遮蔽的检查范围**不限于外层同名变量**，还包括**内置模块名与核心函数名**：
形如 `请 左对齐(文本, 宽度)` 的参数会遮蔽内置模块 `文本`，使函数体内的
`文本.填充(...)` 取到那个参数而非模块。此类遮蔽的报错发生在**调用处**、
真因却在**定义处**，故必须在定义处提醒（`W4001`），并给出改名建议。

#### 6.2.1 高阶函数（函数作为一等公民）

枢言函数是**一等公民**：可赋值给变量、可作为参数传递、可作为返回值。标准库据此提供一组高阶函数，避免用户手写 `当` + `入列` 的循环。

| 函数 | 签名 | 说明 |
|---|---|---|
| `筛选` | `筛选(集合, 判定函数) → 列表` | 保留判定为真的元素 |
| `映射列表` | `映射列表(集合, 变换函数) → 列表` | 逐元素变换 |
| `归约` | `归约(集合, 累积函数, 初值?)` | 折叠为单值；无初值时以首元素起步，空集合且无初值**明确报错** |
| `任何` / `全部` | `(集合, 判定函数) → 布尔` | 短路求值；空集合下 `任何` 为假、`全部` 为真 |
| `查找首个` | `查找首个(集合, 判定函数)` 匹配元素或 `空` | 找不到返回 `空`，不报错 |
| `排序依据` | `排序依据(集合, 取键函数, 倒序?) → 列表` | 稳定排序 |
| `分组依据` | `分组依据(集合, 取键函数) → 映射` | 键 → 该组元素列表 |
| `计数依据` | `计数依据(集合, 取键函数) → 映射` | 键 → 出现次数 |
| `映射值` | `映射值(映射, 变换函数) → 映射` | 保留键，变换值 |

规约：

1. **集合参数**接受列表、文本（逐字）、映射（按键）三种，与 `枚举` 同口径。
2. **真值判断与语言内 `如果` 完全一致** —— 复用同一实现（`values.is_truthy`），不另写一套，避免「标准库认为假、语言认为真」的分裂。
3. **第 2 个参数不是函数时报明确错误**，并给出正确写法示例；不得抛出宿主异常（如 `'int' object is not callable`）。
4. 回调枢言函数需要解释器上下文。静态检查、文档生成等**无解释器**场景下调用会明确报错，而非静默失败。

#### 6.2.2 容器与值的输出表示（`输出` / `转文本`）

`输出` 采用**面向用户**口径：文本**不加引号**。该口径贯穿所有嵌套层级 —— 容器内部的元素同样不加引号。

| 值 | `输出` 结果 |
|---|---|
| `"陈工"` | `陈工` |
| `[1, 2]` | `[1, 2]` |
| `["甲", "乙"]` | `[甲, 乙]` |
| `{"甲": 1}` | `{甲: 1}` |
| `点(横 是 3)` | `点{横: 3}` |
| `员工(姓名 是 "陈工")` | `员工{姓名: 陈工}` |

**硬性约束**：`列表` / `映射` / `结构体` 的容器结构**只能有一个实现**（`values._render`），两种口径（用户 `display` / 调试 `repr`）只是元素渲染策略不同。历史上列表、映射、结构体各写了一份，且映射键用了 Python 的 `{k!r}`，导致同一个文本值在列表里是 `[甲, 乙]`、在映射里却是 `{'甲': 1}` —— 这是同一语义两处实现，属**禁止**项。

调试口径 `repr`（文本加引号）仅用于 Python 层与内部摘要，**不出现在 `输出` 路径上**。

### 6.3 中文处理规约（重点）

1. **所有字符串长度为字符数**（码点），非字节数。`长度("你好")` = 2。
2. **索引从 0 开始**，负索引表示从末尾（-1 为最后一个字符）。
3. **截取** `截取(文本, 起, 长)` 按字符。
4. `逐字("你好")` 迭代出 `"你"`、`"好"`（按码点，不按 UTF-16 代理对，不做字形簇合并——v0.1 明确限制，路线图中标注 grapheme cluster 支持）。
5. **不做隐式分词**。标准库不提供「智能分词」，避免与语言语法纠缠（分词属应用层能力，走路线图 NLP 模块）。
6. 输入输出统一使用 UTF-8；Windows 控制台强制切到 UTF-8 代码页，避免乱码。

### 6.4 标准库错误

标准库失败以**异常**抛出，异常值为**映射**：`{"类型": "文件错误", "信息": "...", "路径": "..."}`。捕获后可读 `异常["信息"]`。

## 7. 格式化与风格规范（规范的一部分）

枢言语言**自带**规范风格，格式化器是规范的落实者，而非独立约定。

| 规则 | 内容 |
|---|---|
| 缩进 | 4 空格，禁用 Tab |
| 块结构 | 开启语句结尾不加额外空格；`结束` 单独成行，与开启语句同缩进 |
| 二元运算 | 运算符两侧各一空格（白话联结词同样） |
| 逗号 | 后接一空格，前不加 |
| 汉字与拉丁混排 | 汉字与标识符之间保留一个空格（`定义 订单_ID`），提升可读性 |
| 字符串 | 优先双引号；含 `"` 时用单引号 |
| 空行 | 函数之间一个空行；函数内逻辑段落可空行 |
| 注释 | `#` 后一个空格 |
| 最大行宽 | 100 **显示列**（汉字按 2 列计） |

> **东亚宽度对齐**：格式化器与诊断系统必须实现 `显示宽度()` —— 汉字/全角 = 2 列，其余 = 1 列。这是中文语言工具链的硬性要求（对齐表格、错误下划线、列号显示都依赖它）。

## 8. 诊断信息规范

### 8.1 输出格式

```
第 5 行，第 9 列：类型错误（D3004）
  不能把「文本」赋值给「整数」变量 年龄。

    5 |     年龄 是 "二十岁"
      |            ^^^^^^^^ 此处得到 文本

  建议：改用 整("二十岁")，或把 年龄 声明为 文本。
```

### 8.2 硬性要求

1. 必须包含**行号与列号**（列按显示列，汉字算 2 列）。
2. 必须包含**诊断码**（便于检索与测试）。
3. 必须包含**源码摘录 + 定位下划线**。
4. 必须包含**修复建议**（`D` 类全部带，`W` 类可选）。
5. 一次编译**报告全部错误**（不遇错即停），最多 50 条后汇总「还有 N 条未显示」。

### 8.3 同类候选（拼写纠错）

`D3005` 未定义标识符时，按**编辑距离**（限定 ≤ 2 或长度比例 ≤ 0.5）列出候选，最多 3 个。

同一候选算法（`_suggest_from`）也用于：结构体字段名、枚举成员名、
函数参数名。**拼写候选只保留一处实现**，避免各处阈值漂移。

### 8.4 禁止静默丢弃（硬性约束）

以下情形**必须报错**，不得静默继续：

| 情形 | 诊断码 |
|---|---|
| 表达式中多出未参与运算的记号（如 `2 的 10`） | `D2001` |
| 表达式语句的值算完就丢（行首运算符断行所致） | `D2012` |
| 嵌套深度超过实现上限（防宿主栈溢出） | `D2013` |
| 内置函数收到具名参数（会被忽略） | `D3007` |
| 用户函数收到未知具名参数（会被忽略） | `D3007` |
| 结构体构造缺少 / 多出 / 未知字段 | `D3017` |
| 读或写不存在的结构体字段 | `D3018` |
| 访问不存在的枚举成员 | `D3019` |
| 整模块引入后**裸用**该模块的类型名 | `D3005`（附改写建议） |
| 按名引入一个模块**没有导出**的名字 | `D3014` |

> **为什么单列一条**：本项目历史上最严重的缺陷都是静默失败
> （`2 的 10 次方` 被算成 `2`、`输出(甲 是 5)` 什么都不做）。
> 静默失败的危险在于**用户以为语言算错了**，而实际上语言只是没说话。
> 宁可多一条刺眼的报错，也不留一个安静的错。

### 8.5 错误恢复：一行一错（v0.2 明确）

一次编译要报告全部错误（§8.2 第 5 条），但**不能因此把一条错误扩散成一串**。

规则：**一条语句报错后，丢弃该行剩余记号，跳到下一行行首**（行级恐慌恢复，`_sync_to_next_line`）。

| 硬性要求 | 说明 |
|---|---|
| **一行一错** | 同一条语句内已报错，后续衍生错误一律**抑制**，不再补刀 |
| **不污染后续行** | 后续行若本来正确，必须零报错 |
| **两处独立错误报两条** | 错误恢复不能「吞掉」后面的真错误 |
| **未闭合括号只报一条** | `输出(1 + 2` 缺 `)` 时，报「参数列表未闭合」一条，不再连带报「表达式缺失」等 |
| **语法错不吞语义错** | 同文件既有语法错又有语义错时，**两类都要报**（见下） |

反例（v0.1 实测，已修）：`定义 乙 == 2` 一行曾报出 **4 条**错误，且把后续正确行也一起报错 —— 用户面对四条错误，实际根因只有一个 `==`，修复成本被凭空放大四倍。

**括号未闭合不得越过语句边界（v0.4.0 明确）**：括号组（调用参数 /
列表字面量 / 映射字面量 / 分组括号）内若出现**换行**或**语句起始关键字**，
即判定该组**未闭合**，立即收尾并报错 —— 报错位置指向**未闭合的那个括号**。

依据在词法层：括号深度大于 0 时**不发出换行记号**，故「组内出现换行」
意味着括号早已配对完毕、组已经结束；而「组内出现语句起始关键字」
则是「括号没闭合、换行被抑制」的唯一可辨识信号。多行参数列表因此
依赖词法层的换行抑制，解析层**不得**自行跳过换行。

反例（v0.4.0 实测，已修）：括号组曾跨过换行继续找配对的右括号，
导致两个后果 —— ① 报错位置落到**下一行的正确语句**上（把人往错方向带）；
② 那一整行被**静默丢弃**，其上的语义错一并消失（`检查` 反而显示
「没有发现问题」）。错误恢复点必须**预计算且只前进、不回退**：
回退会与深层嵌套退栈互相覆盖成环（实测 200 层 `如果` 卡死）。

**语法错不得吞掉语义错（v0.3.1 明确）**：解析器遇错后**仍继续解析**，
产出一棵**部分合法的 AST**；该树必须**继续交给语义分析**，
使语法诊断与语义诊断**一并报告**（按行、列排序）。

反例（v0.3.1 实测，已修）：`lint_source` 曾在解析一遇诊断时就整体返回、
**不跑语义分析** —— 于是文件里只要有一处语法错，同文件所有语义错
（类型不符 `D3004`、未定义 `D3005` …）**一条都不报**。用户改完语法错再跑，
才看到语义错，被迫来回两趟。这违反 §8.2 第 5 条。

> **设计取舍**：行级恢复是**故意保守**的 —— 宁可「一条错误只报一次」而放弃同行后续的发现，也不制造错误洪水。恢复点选「下一行行首」而非「下一个分号」，因为枢言以换行作语句终止（§2.7），分号不是必需。

## 9. 附录：形式语法（EBNF 汇总）

```ebnf
程序        = 语句* EOF ;
语句        = 变量声明 | 常量声明 | 赋值 | 表达式语句 | 分支 | 循环
            | 函数定义 | 返回语句 | 抛出语句 | 尝试语句 | 引入语句
            | 类型声明 | 断言语句 | 块语句 ;
变量声明    = "定义" 标识符 类型标注? ("=" 表达式)? ;
常量声明    = "常量" 标识符 类型标注? "=" 表达式 ;
赋值        = 左值 赋值算符 表达式 ;
赋值算符    = "=" | "+=" | "-=" | "*=" | "/=" | "%=" | "是" ;
分支        = "如果" 表达式 "则"? 块
              ("否则如果" 表达式 块)* ("否则" 块)? "结束" ;
循环        = 条件循环 | 计数循环 | 遍历循环 ;
条件循环    = "当" 表达式 "成立"? 块 "结束" ;
计数循环    = "重复" 表达式 "次" 块 "结束"
            | "重复" 标识符 "从" 表达式 "到" 表达式 ("步长" 表达式)? 块 "结束" ;
遍历循环    = "遍历" 标识符 "中"? 表达式 块 "结束" ;
函数定义    = "请" 标识符 "(" 参数列表? ")" ("返回" 类型)? 块 "结束" ;
参数列表    = 参数 ("," 参数)* ;
参数        = 标识符 类型标注? ("=" 表达式)? | "..." 标识符 ;
返回语句    = "返回" 表达式? ;
抛出语句    = "抛出" 表达式 ;
尝试语句    = "试" 块 ("捕获" 标识符? 块)* ("最终" 块)? "结束" ;
引入语句    = "引入" 字符串 | "引入" "{" 标识符 ("," 标识符)* "}" "从" 字符串 ;
类型声明    = "类型" 标识符 "=" 类型定义 ;
类型定义    = 类型表达式 | 结构体定义 | 枚举定义 ;
类型表达式  = 基础类型 | 标识符 | "[" 类型表达式 "]" ;
结构体定义  = "{" 字段 ("," 字段)* "}" ;
字段        = 标识符 ":" 类型表达式 ;
枚举定义    = "{" 成员 ("," 成员)* "}" ;
成员        = 标识符 ;
断言语句    = "断言" 表达式 ("," 字符串)? ;
块语句      = "{" 语句* "}" | 语句* "结束" ;
表达式      = 或表达式 ;
或表达式    = 且表达式 ("或" 且表达式)* ;
且表达式    = 比较表达式 ("且" 比较表达式)* ;
比较表达式  = 区间表达式 (比较算符 区间表达式)? ;        (* 链式禁止 *)
区间表达式  = 加减表达式 (".." 加减表达式)? ;
加减表达式  = 乘除表达式 (("+"|"-") 乘除表达式)* ;
乘除表达式  = 幂表达式 (("*"|"/"|"%") 幂表达式)* ;
幂表达式    = 一元表达式 ("^" 幂表达式)? ;
一元表达式  = ("-"|"+"|"非") 一元表达式 | 后缀表达式 ;
后缀表达式  = 基础表达式 ( 调用后缀 | 索引后缀 | 成员后缀 )* ;
基础表达式  = 字面量 | 标识符 | "(" 表达式 ")" | 列表字面量 | 映射字面量
            | 函数表达式 | 条件表达式 ;
```

### 10.1 实现现状与已知限制（**如实声明**）

| 维度 | 当前状态 | 计划 |
|---|---|---|
| 执行方式 | **解释器**（遍历 AST 直接求值） | 字节码 VM → 见 §10.2 |
| 性能定位 | 「可用」，非「最快」 | 不追求零开销抽象 |
| 类型系统 | **保守推断**，只在能推的地方推；推不出即 `任意` | 不做 HM / 借用检查 |
| 交互环境 | **无 REPL**（只能 `sy 运行` 文件） | 见 §10.2 |
| 调试能力 | **无调试器**（靠诊断信息定位） | 见 §10.2 |
| 依赖管理 | **无包管理器**（多文件靠 `引入` + 相对路径） | 见 §10.2 |

> **为什么单列此表**：把「没有的」写清楚，与把「有的」写清楚同等重要。用户按文档的承诺来评估工具，若文档暗示存在而实际不存在，信任损失远大于功能缺失本身。

### 10.2 路线图（**均为未实现**，不作现状承诺）

1. **字节码 VM**：编译为中间字节码 + 栈式虚拟机，替换当前 AST 直接遍历的解释执行。
2. **REPL 交互环境**：多行输入（块未闭合时续行）、表达式求值即打印、历史命令、错误不终止会话、`:帮助` 等元命令。
3. **调试器**：断点、单步、变量查看。
4. **包管理器**：模块注册、版本约束、依赖解析。
5. 标准库补 `JSON` / `CSV` 模块（正确处理转义、引号、换行）。
6. 类型系统增强：局部 HM 推断（**不**升级为全程序强制）。
